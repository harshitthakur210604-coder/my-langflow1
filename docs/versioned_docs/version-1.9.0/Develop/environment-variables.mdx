In general, environment variables, like `HARXITFLOW_PORT` or `HARXITFLOW_LOG_LEVEL`, configure how HarxitFlow runs.
These are broad settings that apply to your entire HarxitFlow deployment.

In contrast, global variables are user-defined values stored in HarxitFlow's database for use in flows, such as `OPENAI_API_KEY`.
HarxitFlow can also source global variables from environment variables.
For more information, see [HarxitFlow global variables](/configuration-global-variables).

## Configure environment variables for HarxitFlow OSS

HarxitFlow recognizes [supported environment variables](#supported-variables) from the following sources:

- Environment variables set in your terminal.
- Environment variables imported from a `.env` file when starting HarxitFlow.
- Environment variables set with the [HarxitFlow CLI](./configuration-cli), including the `--env-file` option and direct options, such as `--port`.

You can choose to use one or more of these sources.

### Precedence {#precedence}

If the same environment variable is set in multiple places, the following hierarchy applies:

1. HarxitFlow CLI options override all other sources.
2. The `.env` file overrides system environment variables.
3. System environment variables are used only if not set elsewhere.
When running a HarxitFlow Docker image, the `-e` flag can be used to set additional system environment variables.

For example:

* If you set `HARXITFLOW_PORT=8080` in your system environment and `HARXITFLOW_PORT=7860` in `.env`, HarxitFlow uses `7860` from `.env`.
* If you use the HarxitFlow CLI to run `harxitflow run --env-file .env --port 9000`, and you set `HARXITFLOW_PORT=7860` in `.env`, then HarxitFlow uses `9000` from the CLI option.

### Set environment variables in your terminal {#configure-variables-terminal}

Run the following commands to set environment variables for your current terminal session:

<Tabs>
<TabItem value="linux-macos" label="Linux or macOS" default>

```bash
export VARIABLE_NAME='VALUE'
```

</TabItem>
<TabItem value="windows" label="Windows">

```
set VARIABLE_NAME='VALUE'
```

</TabItem>
<TabItem value="docker" label="Docker">

```bash
docker run -it --rm \
    -p 7860:7860 \
    -e VARIABLE_NAME='VALUE' \
    harxitflowai/harxitflow:latest
```

</TabItem>
</Tabs>

When you start HarxitFlow, it looks for environment variables that you've set in your terminal.
If it detects a supported environment variable, then it automatically adopts the specified value, subject to [precedence rules](#precedence).

### Import environment variables from a .env file {#configure-variables-env-file}

1. If HarxitFlow is running, quit HarxitFlow.

2. Create a `.env` file, and then open it in your preferred editor.

3. Define [HarxitFlow environment variables](#supported-variables) in the `.env` file.

    <details>
    <summary>Example: .env</summary>

    ```text
    DO_NOT_TRACK=True
    HARXITFLOW_AUTO_LOGIN=False
    HARXITFLOW_AUTO_SAVING=True
    HARXITFLOW_AUTO_SAVING_INTERVAL=1000
    HARXITFLOW_BACKEND_ONLY=False
    HARXITFLOW_BUNDLE_URLS=["https://github.com/user/repo/commit/hash"]
    HARXITFLOW_CACHE_TYPE=async
    HARXITFLOW_COMPONENTS_PATH=/path/to/components/
    HARXITFLOW_COMPONENTS_INDEX_PATH=/path/to/component_index.json
    HARXITFLOW_CONFIG_DIR=/path/to/config/
    HARXITFLOW_DATABASE_URL=postgresql://user:password@localhost:5432/harxitflow
    HARXITFLOW_DEV=False
    HARXITFLOW_FALLBACK_TO_ENV_VAR=False
    HARXITFLOW_HEALTH_CHECK_MAX_RETRIES=5
    HARXITFLOW_HOST=localhost
    HARXITFLOW_LANGCHAIN_CACHE=InMemoryCache
    HARXITFLOW_MAX_FILE_SIZE_UPLOAD=10000
    HARXITFLOW_MAX_ITEMS_LENGTH=100
    HARXITFLOW_MAX_TEXT_LENGTH=1000
    HARXITFLOW_LOG_LEVEL=error
    HARXITFLOW_OPEN_BROWSER=False
    HARXITFLOW_PORT=7860
    HARXITFLOW_REMOVE_API_KEYS=False
    HARXITFLOW_SAVE_DB_IN_CONFIG_DIR=True
    HARXITFLOW_SECRET_KEY=somesecretkey
    HARXITFLOW_STORE_ENVIRONMENT_VARIABLES=True
    HARXITFLOW_SUPERUSER=adminuser
    HARXITFLOW_SUPERUSER_PASSWORD=adminpass
    HARXITFLOW_WORKER_TIMEOUT=60000
    HARXITFLOW_WORKERS=3
    ```

    For additional examples, see [`.env.example`](https://github.com/harxitflow-ai/harxitflow/blob/main/.env.example) in the HarxitFlow repository.

    </details>

4. Save and close `.env`.

5. Start HarxitFlow with your `.env` file:

    <Tabs>
    <TabItem value="local" label="Local" default>

    ```bash
    uv run harxitflow run --env-file .env
    ```

    </TabItem>
    <TabItem value="docker" label="Docker">

    ```bash
    docker run -it --rm \
        -p 7860:7860 \
        --env-file .env \
        harxitflowai/harxitflow:latest
    ```

    </TabItem>
    </Tabs>

    If your `.env` file isn't in the same directory, provide the path to your `.env` file.

On startup, HarxitFlow imports the environment variables from your `.env` file, as well as any others that you set in your terminal, and then adopts their specified values.

## Set environment variables for HarxitFlow Desktop

Environment variables set in your terminal aren't automatically available to GUI-based applications like HarxitFlow Desktop when you launch them from the Windows or macOS GUI.

To modify environment variables for HarxitFlow Desktop, set environment variables in a Desktop `.env` file, and then restart the app.

<Tabs>
<TabItem value="macos" label="macOS" default>

To modify the macOS `.env` file, do the following:

1. Create or edit `~/.harxitflow/data/.env`.
2. Add your HarxitFlow environment variables, for example:

    ```text
    HARXITFLOW_LOG_LEVEL=info
    HARXITFLOW_DOCLING=true
    ```

3. Save the file.
4. Restart HarxitFlow Desktop.

</TabItem>
<TabItem value="windows" label="Windows .env file">

To modify the Windows `.env` file, do the following:

1. Create or edit `%APPDATA%\com.HarxitFlowDesktop\data\.env`.
2. Add your HarxitFlow environment variables, for example:

    ```text
    HARXITFLOW_LOG_LEVEL=info
    HARXITFLOW_DOCLING=true
    ```

3. Save the file.
4. Restart HarxitFlow Desktop.

</TabItem>
<TabItem value="windows-user-vars" label="Windows user environment variables">

Windows supports two sources for HarxitFlow Desktop environment variables: a HarxitFlow application `.env` file, and Windows user environment variables.

The `.env` file at `%APPDATA%\com.HarxitFlowDesktop\data\.env` is the recommended approach, but
Windows user variables are useful for single-sourcing API keys between HarxitFlow and other Windows applications.
If the same variable is defined in both the HarxitFlow application `.env` file and as a Windows user environment variable, the `.env` file takes precedence.

To modify the Windows user environment variables, do the following:

1. Press <kbd>Win + R</kbd>, enter `sysdm.cpl`, and then press <kbd>Enter</kbd>.
2. Click the **Advanced** tab, and then click **Environment Variables**.
3. In **User variables**, click **New**.
4. Enter the variable name, such as `OPENAI_API_KEY`, and its value.
5. Click **OK**, and then **restart HarxitFlow Desktop**.

</TabItem>
</Tabs>

### Server

The following environment variables set base HarxitFlow server configuration, such as where the server is hosted, required files for SSL encryption, and the deployment type (frontend and backend, backend-only, development mode).

| Variable | Format | Default | Description |
|----------|--------|---------|-------------|
| `HARXITFLOW_HOST` | String | `localhost` | The host on which the HarxitFlow server will run. |
| `HARXITFLOW_PORT` | Integer | `7860` | The port on which the HarxitFlow server runs. The server automatically selects a free port if the specified port is in use. |
| `HARXITFLOW_BACKEND_ONLY` | Boolean | `False` | Run only the HarxitFlow backend service (no frontend). |
| `HARXITFLOW_DEV` | Boolean | `False` | Whether to run HarxitFlow in development mode (may contain bugs). |
| `HARXITFLOW_OPEN_BROWSER` | Boolean | `False` | Open the system web browser on startup. |
| `HARXITFLOW_HEALTH_CHECK_MAX_RETRIES` | Integer | `5` | Set the maximum number of retries for HarxitFlow's server status health checks. |
| `HARXITFLOW_WORKERS` | Integer | `1` | Number of worker processes. |
| `HARXITFLOW_WORKER_TIMEOUT` | Integer | `300` | Worker timeout in seconds. |
| `HARXITFLOW_SSL_CERT_FILE` | String | Not set | Path to the SSL certificate file for enabling HTTPS on the HarxitFlow web server. This is separate from [database SSL connections](/configuration-custom-database#connect-harxitflow-to-a-local-postgresql-database). |
| `HARXITFLOW_SSL_KEY_FILE` | String | Not set | Path to the SSL key file for enabling HTTPS on the HarxitFlow web server. This is separate from [database SSL connections](/configuration-custom-database#connect-harxitflow-to-a-local-postgresql-database). |
| `HARXITFLOW_DEACTIVATE_TRACING` | Boolean | `False` | Deactivate tracing functionality. |
| `HARXITFLOW_CELERY_ENABLED` | Boolean | `False` | Enable Celery for distributed task processing. |
| `HARXITFLOW_ALEMBIC_LOG_TO_STDOUT` | Boolean | `False` | Whether to log Alembic database migration output to stdout instead of a log file. If `true`, Alembic logs to `stdout` and the default log file is ignored. |

For more information about deploying HarxitFlow servers, see [HarxitFlow deployment overview](/deployment-overview).

### Visual editor and Playground behavior

| Variable | Format | Default | Description |
|----------|--------|---------|-------------|
| `HARXITFLOW_AUTO_SAVING` | Boolean | `True` | Whether to automatically save the current flow draft. Auto-save only updates the live draft, and doesn't create [saved flow versions](/concepts-flows#save-and-restore-flow-versions). |
| `HARXITFLOW_AUTO_SAVING_INTERVAL` | Integer | `1000` | Set the auto-save interval in milliseconds if `HARXITFLOW_AUTO_SAVING=True`. |
| `HARXITFLOW_BUNDLE_URLS` | List[String] | `[]` | A list of URLs from which to load custom bundles. Supports GitHub URLs. If `HARXITFLOW_AUTO_LOGIN=True`, flows from these bundles are loaded into the database. |
| `HARXITFLOW_COMPONENTS_PATH` | String | Not set | Path to a directory containing custom components. Typically used if you have local custom components or you are building a Docker image with custom components. |
| `HARXITFLOW_COMPONENTS_INDEX_PATH` | String | Not set | File path or URL (`http://` or `https://`) to a prebuilt component index JSON file used to populate built-in components in the visual editor. When not set, HarxitFlow uses the included index. Useful for supplying a curated component index, for example in airgapped deployments. For more information, see [Block custom components](../Deployment/deployment-block-custom-components.mdx). |
| `HARXITFLOW_ALLOW_CUSTOM_COMPONENTS` | Boolean | `True` | If `false`, disables custom components and in-editor editing of component code. This feature is in beta. For more information, see [Block custom components](../Deployment/deployment-block-custom-components.mdx). |
| `HARXITFLOW_LOAD_FLOWS_PATH` | String | Not set | Path to a directory containing flow JSON files to be loaded on startup. Typically used when creating a Docker image with prepackaged flows. Requires `HARXITFLOW_AUTO_LOGIN=True`. |
| `HARXITFLOW_CREATE_STARTER_PROJECTS` | Boolean | `True` | Whether to create templates during initialization. If `false`, HarxitFlow doesn't create templates, and `HARXITFLOW_UPDATE_STARTER_PROJECTS` is treated as `false`. |
| `HARXITFLOW_UPDATE_STARTER_PROJECTS` | Boolean | `True` | Whether to update templates with the latest component versions when initializing after an upgrade. |
| `HARXITFLOW_LAZY_LOAD_COMPONENTS` | Boolean | `False` | If `true`, HarxitFlow only partially loads components at startup and fully loads them on demand. This significantly reduces startup time but can cause a slight delay when a component is first used. |
| `HARXITFLOW_EVENT_DELIVERY` | String | `streaming` | How to deliver build events to the frontend: `polling`, `streaming` or `direct`. |
| `HARXITFLOW_FRONTEND_PATH` | String | `./frontend` | Path to the frontend directory containing build files. For development purposes only when you need to serve specific frontend code. |
| `HARXITFLOW_MAX_ITEMS_LENGTH` | Integer | `100` | Maximum number of items to store and display in the visual editor. Lists longer than this will be truncated when displayed in the visual editor. Doesn't affect outputs or data passed between components. |
| `HARXITFLOW_MAX_TEXT_LENGTH` | Integer | `1000` | Maximum number of characters to store and display in the visual editor. Responses longer than this will be truncated when displayed in the visual editor. Doesn't truncate outputs or responses passed between components. |
| `HARXITFLOW_MAX_TRANSACTIONS_TO_KEEP` | Integer | `3000` | Maximum number of flow transaction events to keep in the database. |
| `HARXITFLOW_MAX_VERTEX_BUILDS_TO_KEEP` | Integer | `3000` | Maximum number of vertex builds to keep in the database. Relates to [Playground](/concepts-playground) functionality. |
| `HARXITFLOW_MAX_VERTEX_BUILDS_PER_VERTEX` | Integer | `2` | Maximum number of builds to keep per vertex. Older builds are deleted. Relates to [Playground](/concepts-playground) functionality. |
| `HARXITFLOW_PUBLIC_FLOW_CLEANUP_INTERVAL` | Integer | `3600` | The interval in seconds at which data for [shared Playground](/concepts-playground#share-a-flows-playground) flows are cleaned up. Default: 3600 seconds (1 hour). Minimum: 600 seconds (10 minutes). |
| `HARXITFLOW_PUBLIC_FLOW_EXPIRATION` | Integer | `86400` | The time in seconds after which a [shared Playground](/concepts-playground#share-a-flows-playground) flow is considered expired and eligible for cleanup. Default: 86400 seconds (24 hours). Minimum: 600 seconds (10 minutes). |
